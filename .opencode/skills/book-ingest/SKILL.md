# Book Ingest — добавление книги в библиотеку

Цель репозитория: книги в виде, удобном для консультаций агента (progressive disclosure):
компактные карты (INDEX.md, topics.md) + полные главы в Markdown + точечный grep.
Каждая книга живёт в двух видах: нетронутый оригинал в `originals/` и проработанная версия в `library/<slug>/`.

Прочитай `README.md` в корне репозитория для контекста, если ещё не читал.

## Workflow

1. **Оригинал.** Положи файл в `originals/` (не изменяй его имя содержательно; пробелы допустимы).

2. **Параметры инжеста.** Определи вместе с пользователем:
   - `slug` — короткий id книги для `library/<slug>` (например `ddia-2e`, `designing-machines`);
   - точное название, авторов, редакцию, год (обычно видно из имени файла/метаданных).

3. **Конвертация.** Скрипт требует только python3 (stdlib). Формат вызова:

   ```sh
   python3 .opencode/skills/book-ingest/scripts/epub_to_md.py \
     originals/<file.epub> library/<slug> \
     --slug <slug> --title "<Title, Edition>" \
     --authors "Author One, Author Two" --edition "2nd Edition" --year 2026
   ```

   Скрипт создаёт: `metadata.yaml`, `INDEX.md`, `glossary.md`, `chapters/*.md` (по файлу на главу,
   YAML frontmatter: title, chapter, sections, words), `assets/`. Пропускает служебные страницы
   (cover, copyright, dedication, colophon) и back-of-book индекс по номерам страниц (он бесполезен
   без маппинга страниц). Ссылки между главами (xref) конвертируются в markdown-ссылки с якорями,
   сноски — в markdown footnotes, таблицы — в md-таблицы, сайдбары — в цитаты.

   Если исходник не epub, а **pdf**: предложи найти epub (качество конвертации несравнимо выше).
   Если epub нет совсем —(pdftotext с `-layout` вручную, затем ручная разбивка по главам) — последний вариант,
   предупреди, что качество будет хуже и QA нужно делать тщательнее.

4. **QA (обязательно, не пропускай).** Проверь выборочно:
   - `INDEX.md` читабелен; у каждой главы есть секции и правдоподобный счётчик слов;
   - начало случайной главы: frontmatter, `# Заголовок`, `**Sections:**`, текст без html-мусора;
   - кусок кода из главы с примерами (отступы/пробелы не схлопнуты, ```-fence с языком);
   - таблица (если есть) выглядит как md-таблица; картинки ссылаются на `../assets/...` и файлы существуют;
   - сноски: `[^id]` в тексте и `[^id]:` в конце файла соответствуют друг другу;
   - `grep -rn "]())" chapters/` и `grep -rn "<aside\|<div " chapters/` пусты.
   При дефектах — правь `scripts/epub_to_md.py` (это общий инструмент, дефект скорее всего системный)
   и перезапускай инжест. Перед повтором удаляй ТОЛЬКО генерируемые артефакты
   (`chapters/`, `assets/`, `INDEX.md`, `glossary.md`, `metadata.yaml`) — никогда не удаляй
   `library/<slug>` целиком, чтобы не потерять кураторский `topics.md`.

5. **topics.md (кураторский шаг, руками агента).** Прочитай `INDEX.md` и пролистай `Summary`-секции
   глав, затем напиши `library/<slug>/topics.md`:
   - 10–20 тем инженерных консультаций, которые покрывает книга;
   - для каждой: типовые вопросы (можно на русском), главы/секции (точные английские названия секций —
     они grep-абельны), 4–6 grep-терминов;
   - в конце — короткий протокол консультации (INDEX → grep → точечное чтение → ответ с цитатой главы/секции).
   Скрипт никогда не перезаписывает `topics.md`.

6. **README.** Если книга первая — README уже написан. Проверь только, что описание структуры
   соответствует действительности. Отдельной «таблицы книг» нет: список книг = `ls library/`.

7. **Закоммить.** Один коммит: `ingest <slug>: <Title>` (оригинал + библиотека + правки скрипта).

## Что НЕ делать

- Не редактируй файлы в `library/<slug>/chapters/`, `INDEX.md`, `glossary.md`, `metadata.yaml` руками —
  они регенерируются. Баг рендеринга = правка скрипта + re-ingest.
- Не трогай `originals/`.
- Не добавляй в библиотеку полностью сгенерированные пересказы вместо текста книги —
  ценность именно в исходном тексте + навигации.
